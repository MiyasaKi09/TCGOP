# RULES-DECISIONS — one decision per §8 item of PORT-SPEC.md

Scope: the 21 confirmed bugs (§8.1) and the 39 under-specified semantics (§8.2).
Product-owner mandate: **fix the bugs, complete the missing features**. The card text in
`src/data/cards/*.ts` (mirrored in `rust/crates/engine/src/cards/*.rs`) plus the rulebook
conventions quoted in the spec are the specification; where the intent is genuinely ambiguous the
most natural reading of the card text is chosen and flagged as such.

Invariants that constrain every decision below:

* determinism — no clock, no `rand`, only `EngineRng` through `EngineContext`;
* serde wire compatibility — new `GameAction` variants keep `#[serde(tag = "type")]` with a
  camelCase discriminator; every new struct field is `Option<T>` with
  `#[serde(default, skip_serializing_if = "Option::is_none")]`;
* every existing test stays green unless it encoded the bug (those are listed in the `tests` column
  with the reason);
* behaviour **not** listed in §8 is never changed — parity elsewhere is a feature.

`status` legend: **FIX** (bug repaired), **FEATURE** (missing rule implemented),
**SEMANTICS** (rule pinned down, usually inert on the shipped catalogue), **SKIP** (deliberately no
engine change — rationale given).

## Appendix A — new engine surface introduced by these decisions

Added once here so the per-item rows can reference it.

### New `GameAction` variant

```rust
#[serde(rename = "useSurcharge")]
UseSurcharge {
    target_instance_id: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    target_is_captain: Option<bool>,
},
```

Item 34. Captain **special** attacks reuse the existing
`CaptainAttack { target_instance_id, target_is_captain, is_special: Some(true) }` — the field
already exists on the wire and in the UI contract (§7.3), so no `captainSpecialAttack` variant is
created. No `captainRectoAttack` variant is created either: `recto.attacks` is `[]` in all four
captain definitions and `captains.ts` states the rule verbatim —
`// Le Capitaine recto ne peut pas attaquer (Rulebook v3.1 §2.1).`

`EquipObject` grows one optional field for the same reason (item 28 follow-up), which keeps the
existing wire shape byte for byte:

```rust
#[serde(rename = "equipObject")]
EquipObject {
    object_instance_id: String,
    target_instance_id: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    target_is_captain: Option<bool>,
},
```

### New enum variants

* `StatusEffectType::Taunt` (item 38, `"taunt"`) — the bearer must target `source` while that
  instance is a legal target.
* `SpecialAttack` gains structured fields `taunt: Option<bool>`, `cleanse: Option<bool>`,
  `buff_ally_atk: Option<i32>` (item 38/54) so the three text-only support specials
  (`RH-004` Provocation, `BW-007` Peinture de la Colère, `RH-006` Stimulant) stop being free-text.
  The TS card data and the Rust card modules are edited **in lockstep** (§8.54).
